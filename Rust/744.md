# Euler Problem 744 Solution in Rust

I'll solve Euler Problem 744, which asks for the number of ways to write a number as a sum of distinct positive integers, where the order doesn't matter (partitions into distinct parts).

## Problem Understanding

The problem asks for the number of partitions of a number n into distinct positive integers. For example, for n=6:
- 6 = 6
- 6 = 5 + 1  
- 6 = 4 + 2
- 6 = 3 + 2 + 1

So there are 4 ways.

## Solution Approach

I'll use dynamic programming with a 2D array where `dp[i][j]` represents the number of ways to partition `i` using distinct integers up to `j`.

## Rust Implementation

```rust
fn solve_euler_744(n: usize) -> u64 {
    // dp[i][j] = number of ways to partition i using distinct integers up to j
    let mut dp = vec![vec![0u64; n + 1]; n + 1];
    
    // Base case: there's one way to partition 0 (using no numbers)
    for j in 0..=n {
        dp[0][j] = 1;
    }
    
    // Fill the dp table
    for i in 1..=n {
        for j in 1..=n {
            // We can either include j or not include j
            dp[i][j] = dp[i][j - 1]; // Don't use j
            
            if i >= j {
                // Use j, and we can't use j again (distinct parts)
                dp[i][j] += dp[i - j][j - 1];
            }
        }
    }
    
    dp[n][n]
}

fn main() {
    let result = solve_euler_744(1000);
    println!("Euler Problem 744 answer: {}", result);
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_small_cases() {
        // Test cases for small values
        assert_eq!(solve_euler_744(1), 1);  // 1
        assert_eq!(solve_euler_744(2), 1);  // 2
        assert_eq!(solve_euler_744(3), 2);  // 3; 2+1
        assert_eq!(solve_euler_744(4), 2);  // 4; 3+1
        assert_eq!(solve_euler_744(5), 3);  // 5; 4+1; 3+2
        assert_eq!(solve_euler_744(6), 4);  // 6; 5+1; 4+2; 3+2+1
    }
}
```

## Alternative Optimized Solution

Here's a more memory-efficient version using a 1D array approach:

```rust
fn solve_euler_744_optimized(n: usize) -> u64 {
    // Using the recurrence relation for partitions into distinct parts
    // This is based on the generating function approach
    
    let mut dp = vec![0u64; n + 1];
    dp[0] = 1;
    
    // For each number from 1 to n
    for i in 1..=n {
        // Process backwards to avoid using updated values
        for j in (i..=n).rev() {
            dp[j] += dp[j - i];
        }
    }
    
    dp[n]
}

fn main() {
    let result = solve_euler_744_optimized(1000);
    println!("Euler Problem 744 answer: {}", result);
}
```

## Key Insights

1. **Dynamic Programming Approach**: We build up solutions for smaller numbers and use them to solve larger ones
2. **Distinct Parts Constraint**: Once we use a number `j`, we cannot use it again, so we look at partitions of `i-j` using numbers less than `j`
3. **Memory Optimization**: The second approach uses only a 1D array and processes in reverse to avoid overwriting values we need

## Time and Space Complexity

- **Time Complexity**: O(n²)
- **Space Complexity**: O(n) for the optimized version

The optimized solution is more efficient in terms of space and works well for the constraint n = 1000 as required by the problem.
