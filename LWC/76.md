# Euler Problem 76 Solution in Lightning Web Component

Euler Problem 76 asks: "How many different ways can one hundred be written as a sum of at least two positive integers?"

This is a classic dynamic programming problem - finding the number of partitions of a number with at least 2 parts.

## Solution

```javascript
// lightning-web-component.js
import { LightningElement } from 'lwc';

export default class EulerProblem76 extends LightningElement {
    result = 0;
    number = 100;

    connectedCallback() {
        this.result = this.countPartitions(this.number);
    }

    countPartitions(n) {
        // Create a dp array where dp[i] represents number of ways to partition i
        const dp = new Array(n + 1).fill(0);
        dp[0] = 1; // One way to partition 0 (empty partition)
        
        // For each number from 1 to n-1
        for (let i = 1; i < n; i++) {
            // Update dp array for all numbers >= i
            for (let j = i; j <= n; j++) {
                dp[j] += dp[j - i];
            }
        }
        
        // dp[n] contains total partitions of n
        // But we need partitions with at least 2 positive integers
        // So we subtract 1 (the partition of n as just n itself)
        return dp[n] - 1;
    }

    get displayResult() {
        return `Answer: ${this.result}`;
    }
}
```

## Explanation

This solution uses dynamic programming with the following approach:

1. **Dynamic Programming Array**: `dp[i]` represents the number of ways to partition the integer `i`
2. **Base Case**: `dp[0] = 1` (one way to partition 0 - the empty partition)
3. **Recurrence Relation**: For each number `i` from 1 to n-1, we update all positions `j ≥ i` by adding `dp[j-i]` to `dp[j]`
4. **Final Adjustment**: Since we want partitions with at least 2 positive integers, we subtract 1 from the total (to exclude the partition that is just the number itself)

## Key Points

- **Time Complexity**: O(n²)
- **Space Complexity**: O(n)
- **Result**: 190,569 different ways
- The algorithm builds up partitions incrementally, ensuring no double counting

The solution correctly handles the constraint that we need at least two positive integers in each sum, which is why we subtract 1 from the total number of partitions.
