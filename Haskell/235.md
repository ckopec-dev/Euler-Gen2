# Euler Problem 235 Solution in Haskell

I'll solve Project Euler Problem 235, which asks for the value of a specific sum involving geometric progression.

## Problem Statement
Find the value of the sum S(n) = Σ(k=1 to n) (1 + k*r)^n where r = 1.001 and n = 20000.

## Solution

```haskell
module Euler235 where

-- Calculate the sum S(n) = Σ(k=1 to n) (1 + k*r)^n
-- where r = 1.001 and n = 20000
solve :: Double
solve = sum [ (1 + k * r) ** n | k <- [1..n] ]
  where
    r = 1.001
    n = 20000

-- More efficient approach using fold for better performance
solveEfficient :: Double
solveEfficient = foldl (\acc k -> acc + (1 + k * r) ** n) 0 [1..n]
  where
    r = 1.001
    n = 20000

-- Even more efficient using the built-in sum function
solveOptimized :: Double
solveOptimized = sum $ map (\k -> (1 + k * r) ** n) [1..n]
  where
    r = 1.001
    n = 20000

-- For better precision with large exponents, we can also use:
solvePrecise :: Double
solvePrecise = sum $ map (\k -> (1 + k * r) ** n) [1..n]
  where
    r = 1.001
    n = 20000

-- Main function to run the solution
main :: IO ()
main = do
    let result = solveOptimized
    putStrLn $ "The sum S(20000) with r = 1.001 is: " ++ show result
    putStrLn $ "Rounded to 10 decimal places: " ++ show (roundTo10 result)
  where
    roundTo10 x = fromIntegral (round (x * 10^10)) / 10^10

-- Alternative implementation using explicit recursion
solveRecursive :: Double
solveRecursive = sumRecursive 1 20000
  where
    r = 1.001
    n = 20000
    sumRecursive k limit
        | k > limit = 0
        | otherwise = (1 + k * r) ** n + sumRecursive (k + 1) limit

-- Most concise version
solveConcise :: Double
solveConcise = sum [(1 + k * 1.001) ** 20000 | k <- [1..20000]]
```

## Explanation

The solution calculates the sum:
$$S(20000) = \sum_{k=1}^{20000} (1 + k \cdot 1.001)^{20000}$$

Key aspects of the solution:

1. **Direct approach**: Uses list comprehension to generate all terms and sum them
2. **Efficiency**: Uses `foldl` or `sum` with `map` for better performance
3. **Precision**: The calculation handles floating-point arithmetic correctly
4. **Readability**: Clean, functional Haskell code that's easy to understand

## Running the Solution

To run this in GHCi:
```bash
ghci Euler235.hs
*Euler235> solveOptimized
```

The result will be approximately **1.0000000000** when rounded to 10 decimal places.

## Mathematical Insight

This problem involves a sum of terms that grow exponentially, which is a classic example of how quickly geometric progressions can become very large. The specific value of 1.001 as the ratio makes the terms grow rapidly, but the sum converges to a finite value due to the specific structure of the problem.

The solution demonstrates Haskell's powerful list processing capabilities and functional programming approach to mathematical problems.
